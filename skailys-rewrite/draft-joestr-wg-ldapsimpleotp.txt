 Lightweight Directory Access Protocol: Simple Authentication with OTP
                  draft-joestr-wg-ldapsimpleotp-latest

Abstract

   This document describes an additional authentication choice for the
   Lightweight Directory Access Protocol (LDAP) which consists of
   credentials in the form of name, password, and a one-time password
   (OTP).

1.1.  Scope

   This document defines the simpleotp alternative of the LDAP
   AuthenticationChoice and how it is used in a Bind operation.

   This document does not constrain how an OTP value is generated or
   verified, and it does not specify how OTP mechanisms are provisioned
   or how shared secrets are distributed.

2.2.  LDAP Bind request

   The 'Bind request' is defined as follows in (RFC 4511, Section 4.2)
   (https://www.rfc-editor.org/info/rfc4511/#section-4.2):

      BindRequest ::= [APPLICATION 0] SEQUENCE { version INTEGER (1 ..
      127), name LDAPDN, authentication AuthenticationChoice }

   form of a keyword and a non-negative integer tag.  Additional the
   method shall be classified by the registrant (RFC 4520, Section 3.7)

3.1.  Simple Authentication Method with OTP

   The 'Simple Authentication Method with OTP', or short 'Simple OTP',
   is a way to present the LDAP server a password and a OTP value.

   The 'Simple OTP' as an 'AuthenticationChoice' is defined as:

   SimpleOTP ::= SEQUENCE { \ password OCTET STRING, \ otpvalue OCTET
   STRING }

   Text based passwords and OTP value transferred to the server using
   the 'simpleotp' 'AuthenticationChoice' SHALL be transferred as

   (https://www.rfc-editor.org/info/rfc3629/) encoded Unicode.

4.  Extending of LDAP AuthenticationChoices

   This document extends the AuthenticationChoice with a new
   alternative, SimpleOTP, identified by the context-specific tag [4].

   AuthenticationChoice ::= CHOICE { \ simple [0] OCTET STRING, \ -- 1
   and 2 reserved \ sasl [3] SaslCredentials, \ simpleotp [4] SimpleOTP
   ... }

5.  Classification

   This document classifies Simple OTP as LIMITED USE, the same usage
   that is assigned to the simple method in the IANA registry of LDAP
   authentication methods [IANA-LDAP].  This classification reflects
   [reason].

   --- https://www.iana.org/assignments/ldap-parameters#ldap-
   parameters-7

6.  Server Behavior

   A server that implements this document but does not support Simple
   OTP for a given Bind request MUST return a BindResponse with the
   resultCode 'authMethodNotSupported' (RFC 4511, Section 4.2)
   (https://www.rfc-editor.org/info/rfc4511/#section-4.2).

   A client that receives authMethodNotSupported in response to a Bind
   request using the SimpleOTP AuthencticationChoice MUST NOT fall back
   to the simple alternative unless it is explicitly configured to do
   so.

7.  Implementation Considerations

   The one-time password is opaque to the protocol defined in this
   document.  A server could, for example, verify it using HOTP (RFC
   4226) (https://www.rfc-editor.org/info/rfc4226) or TOTP (RFC 6238)
   (https://www.rfc-editor.org/info/rfc4226).  This document does not
   require either.

8.  IANA Considerations

   IANA SHOULD assign a new 'Bind authentication' method with following
   properties:

   *  Method: simpleotp

   *  Value: 4

   *  Owner: IESG

   *  Usage: LIMITED USE
